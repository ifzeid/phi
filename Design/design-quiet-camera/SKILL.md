# 极简相机设计

把「安静取景、精密操控」转化为可编辑、可扩展的界面。让摄影画面成为主角，通过排版、几何与适量强调色形成辨识度。

## 依据与边界

- 先阅读 [视觉规范](references/visual-system.md)。涉及新页面或控件状态时，再阅读 [布局与状态](references/layout-and-states.md)。需定位原稿时，阅读 [来源与基线](references/source-and-baseline.md)。
- 把本技能视为 2026-10-28 探索稿的延续规则，不视为已批准的完整产品需求。
- 优先遵循用户当前指示，其次是用户新提供的设计稿，再次是本技能基线。说明重要差异，不为可逆的细小选择反复提问。
- 默认沿 B / 安静取景展开，借用 A 的参数排版。将其说明为工作默认值，不声称用户已经选定 B。
- 将 Quiet Camera、Camera Study 等名称视为工作称呼，不据此创造正式品牌或功能承诺。

## 工作流程

1. **确定任务与状态。** 区分延展界面、比较方案、评审、写 spec 和实现代码；明确用户要拍摄、调整还是浏览。不把每次任务扩展成完整产品。
2. **核对材料。** 上下文充分时直接工作。需要读取或修改 Figma 时，使用当前 Figma 技能与工具，先查验目标节点、组件、变量和字体。节点失效时重新定位；不能读取时说明限制，不假装看过。
3. **建立层级。** 依次安排画面、快门、当前焦段或待调整参数、次级工具。默认把不常用参数收进展开面板，不为专业感堆叠常驻读数。
4. **应用视觉体系。** 使用规定的色彩、字体和几何规则，优先复用兼容组件与 token，只补齐任务必需的缺失部分。不导入无关钱包系统的视觉样式。
5. **完成关键状态。** 按任务覆盖默认、选中、调节、不可用、处理中或异常。固定默认与面板展开态的快门位置。把未确认功能标为假设或建议。
6. **适配输出媒介。** Figma 使用可编辑文字、矢量、组件实例与合理 Auto Layout；代码使用语义 token 和可访问控件。需要新图时使用可用的图像生成工具；图片只承担照片内容，不把完整 UI 烘焙成图片。
7. **检查实际结果。** 在目标尺寸渲染并检查。视觉探索至少检查手机原尺寸；实现或生产交付再检查长文案、大文字及目标设备。修正遮挡、裁切、低对比、错误字体和数值与刻度不一致后交付。
8. **简洁交付。** 链接真实产物，说明设计决定、验证结果与待确认事项。默认中文沟通，UI 沿用指定语言。不声称静态稿已实现手势、动画或真实相机能力。

## 核心规则

- 以近黑为底、石墨灰为面板、柔和白为主要文字；橙红用于快门、当前值与关键选中状态。
- 以取景与快速拍摄为第一层体验；用稳定位置和渐进展开支持深入操控。
- 用无衬线处理界面，用等宽字处理参数。不要把所有文案做成微小全大写仪表字。
- 用圆、矩形、直线与开口几何绘制细线图标；保持光学平衡，不复制参考品牌标志。
- 让点击目标大于视觉图形。以至少 44 × 44 pt 为本设计热区起点，并在实现时按目标平台要求核验。
- 保留照片自然颜色与质感，不覆盖品牌滤镜，不为气氛牺牲真实预览。

## 验收

- 首先看到画面与快门，其次找到当前焦段或正在调整的值。
- 图像上的控件在亮、暗照片上均可读；必要时加局部深色底，不只检查一张示意照片。
- 快门水平居中，展开前后位置一致；选中态包含背景、形态或文本变化，不单靠颜色。
- 数值、单位、自动状态、刻度与指示线一致，不照搬样例值。
- 原稿的微小仪表字和设备外框仅是探索表现，不作为生产可读性与安全区硬标准。
- 验证正确字体与可编辑结构；不把示意图片冒充实时取景，不把建议写成已实现能力。
- 只检查任务相关状态和尺寸；通过后停止，不扩大为无关品牌或组件库项目。
